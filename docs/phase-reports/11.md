# Phase 11 — trained candidate ranking

Status: **PASS** for the implemented Phase 11 gates. Dependency: Phase 10 passed at `7b52520`.

## Implemented behavior and files

- `scripts/fixtures.py` emits a train/development-only private access manifest. `src/tracecause/ranking/{features,table}.py` builds cutoff-safe `(episode, cutoff, candidate)` rows from the production normalizer, signal rules and candidate feature function. It never opens test truth or the global private index during training; names/IDs/group labels remain metadata outside the numeric model matrix.
- `src/tracecause/ranking/{train,model}.py` fits in group-aware folds with within-fold median imputation, missing indicators, scaling and episode-weighted logistic regression. It evaluates candidate recall and end-to-end/conditional Hit@1, Hit@3 and MRR, including zero-candidate episodes. The trusted JSON export contains feature order, parameters, training hashes, versions, validation and an exact SHA-256 identity. Runtime reproduces scikit-learn scores without loading pickle/joblib.
- `src/tracecause/cli_ranking.py`, `src/tracecause/cli.py`, `Makefile`: `make train`, `make dev-report`, `make ranker-register`, `make ranker-register-bundled`, `make demo-ranker`; local PostgreSQL registration and version-compatible inference. The operator CLI defaults to a promoted learned scorer, with visible heuristic fallback on absence/corruption. Earlier demo targets explicitly retain heuristic ranking.
- `src/tracecause/investigation/{service,validation,templates}.py`, `src/tracecause/contracts/models.py`, regenerated `contracts/*` and frontend type: development-threshold abstention, actual ranking mode, source-linked standardized contributions, source/order/score/contribution validation, and versioned cache identity.
- `models/candidate-logistic-v3/model.json`, `docs/MODEL_CARD.md`, `docs/{INVESTIGATION,KNOWN_ISSUES,VERSIONS}.md`, `README.md`: committed 2.8 KB reference model, measured development results and operational limits.
- `tests/unit/test_ranker.py`, `tests/integration/test_persistence_jobs.py`: weighted episodes, all-negative fit rejection, small/group-empty folds, no-candidate denominator, deterministic retraining, export parity, tamper/schema rejection, future/gold mutation, train/dev access boundary and real missing-model fallback.

## Repairs and limits

The first table reader used the global private dataset index, which includes held-out group metadata. It was replaced before the final training run by a train/development-only access manifest; a test poisons the global index and omits test truth files to prove the trainer does not read them. The initial output replayed an older report without feature contributions; the template/cache version was advanced. The first cross-validation loop selected folds from rows, potentially omitting a group with zero candidates. It now splits the declared training groups and counts those episodes as pipeline failures. These repairs changed the trained artifact hash; the committed model and results above are from the final version.

The model is a pointwise relevance ranker over a synthetic candidate set, not an identifiable causal model. It uses only one canonical final cutoff per episode in this phase. The development ranking denominator is two groups and 10 identifiable episodes; the threshold's 20% coverage is a substantial limitation. No held-out test label, captured telemetry, calibration or uncertainty interval was inspected or claimed. The wider benchmark and held-out test evaluation belong to Phase 13.
