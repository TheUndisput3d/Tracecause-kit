# Phase16 — Security and recovery: PASS

## Goal and dependencies

Harden the phase15 API/dashboard/worker and prove recovery using actual services and source artifacts. Phases00–15 were complete at local commit8d2a1d5. Review origin: AI under user authorization; independent human validation was not performed. No GitHub push or public deployment.

## Implemented behavior

- Templatev6 filters exposed hypotheses to adequate anomalous services, prevents baseline-only fallback support, adds explicitly labeled baseline examples and narrows claims. An optional provenance version and historical UI notice distinguish old outputs. No frozen scorer weights, benchmark outputs or reported accuracy were changed.
- Generation admission now persists a synced uncertain-call fence across SIGKILL/timeout. Schema probes share admission. Bounded transport reads enforce64KiB and a caller wall deadline; late transport completion cannot reopen the fence. Dedicated-container reconciliation verifies restart/deployment identity and writes a durable receipt. Native automatic reconciliation is deliberately unsupported/fail-closed.
- Snapshot retirement checks readers, pending jobs and saved investigations. Admission and final publication serialize with retirement. Migration0007 records exact source membership; source/hash-validated legacy backfill and empty-graph reconstruction retain original snapshot IDs/timestamps.
- Real pg_dump/pg_restore and immutable-artifact backup/restore tools verify hashes, schema and row counts. Backups reject pending jobs, lock SQL tables while copying, exclude staging/model caches and require new destinations. Artifact publication also syncs shard directories.
- Streaming JSON depth limit64 joins byte limits. Added real boundary tests for deep JSON, absent cookie/CORS authentication, query injection and unavailable dependencies; process tests kill workers, graph builders and artifact writers at deterministic checkpoints. Existing traversal, model-artifact, prompt-injection, source isolation and redaction regressions remain enabled.
- `SECURITY.md`, `RECOVERY.md`, ADR0012, diagnostic Compose files and an internal-database override document the actual controls and limits. Built frontend assets were searched for configured secrets.

## Failures and corrections

The first depth test matched the human error text rather than the safe error code; corrected the assertion. The first process test unpacked the four-value fixture incorrectly; corrected before executing SIGKILL. The first replay harness omitted required temporal/ranking fields; it failed and was retained as `phase16-restore-replay-initial.log`, then corrected and passed. The newer diagnostic Ollama runtime required writable converted manifest metadata; supplied a separate owned metadata cache while keeping original model blobs read-only. The old dashboard transient systemd unit disappeared after stop; recreated it under the phase16 unit name before browser verification. No failures were masked as passes.
