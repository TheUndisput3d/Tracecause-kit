# Phase 12 — MiniShop capture (PASS)

Date: 12 October 2026. Gate status: **PASS**. All 24 frozen-protocol captures are collected, source-audited and explicitly AI-reviewed under user delegation (ADR 0010). No independent human review. Historical partial checkpoints below are superseded by the final acceptance section.

## Implemented

- A separate `tracecause-capture` Compose project runs five role-specific FastAPI services from one non-root image and a digest-pinned OpenTelemetry Collector. Actual HTTPX calls follow storefront → checkout → payment and storefront → checkout → catalog → inventory.
- Private token-protected controls inject payment errors, inventory delay, catalog errors, and checkout caller timeout with an expiring in-memory TTL. Healthy mode and reset verification are available. Public spans exclude control routes and fault names.
- `scripts/capture/minishop.py` implements a bounded 2-request/s loader, fixed 300/300/120-second benchmark stages, short smoke mode, per-stage UTC times and achieved load, fresh Collector files, force flush, cleanup, root-trace partitioning, hashed public bundles and ignored private truth.
- `scripts/capture/audit.py` checks source hashes, computes per-stage server counts/error fractions/median durations, labels unobservable effects, and writes a private audit JSON and review worksheet. It does not auto-approve target sets.
- The audit now checks each benchmark key against the frozen split, mode and seed, checks stage durations, achieved load, service coverage, direct client/server pairing and reset verification, and preserves human worksheet entries on rerun. A conflicting worksheet row aborts before the CSV is replaced.
- `scripts/capture/review.py` validates completed private review rows against the frozen audit, checks service/intervention confirmation, targets, identifiability and self-reported independent attestation, and reports representative mode/split coverage separately from full test-label coverage. It cannot verify the human identity outside the submitted sheet.
- The pinned Collector JSONL output has a 22-span conformance fixture under `data/fixtures/captured-collector/` and a unit test. The fixture is not yet committed while this phase remains in progress. The captured data card records limits and event-time-only replay.

## Repairs and limits

The Collector 0.162.0 rejected the initial `compression: none` setting for its JSON exporter, so it was removed. The storefront initially had only an internal Docker network and its loopback published port was unavailable; adding a separate host-facing network fixed the actual HTTP probe. The CLI import rejected a relative artifact root; the successful run used an absolute path. The first graph build lacked previously staged document artifacts; using the existing unified demo artifact store plus the new immutable smoke artifacts produced a READY snapshot. The first captured investigation failed because its real baseline ended between ten-second signal boundaries. The initial repair rounded that boundary upward. Subsequent inspection found this could admit intervention spans into the baseline; that repair and its diagnostic outputs are superseded by the downward-boundary repair below. These failures are retained here because static Compose validation alone would not have found them.

The full 24-run capture is underway and must be audited before the gate can pass. The smoke baseline is intentionally too short for meaningful anomaly inference. Collector/SDK dropped-span counters have not been independently measured. Captured target sets and approximately 120 evaluation questions still require independent human review. No held-out, production or large-benchmark performance is claimed.
