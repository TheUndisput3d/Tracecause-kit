# Phase 00 — foundation and verified versions

Date: 2026-10-10. Status: **PASS** for the Phase 00 acceptance gate (R01). This report describes work executed on Linux x86_64 with Python 3.12.3, uv 0.11.19, Docker Engine 29.5.0, Compose 5.1.3, and a project-local Node 24.21.0 executable. Host Node 20.20.2 was below the selected baseline.

## Goal and dependency

Start from the supplied planning kit, which had no application source or Git repository. Create a runnable, locked foundation and verify real database connections. No domain pipeline or generated benchmark is part of this phase.

- `pyproject.toml`, `uv.lock`, `src/tracecause/`, `tests/unit/test_foundation.py`: CLI doctor, optional real-database driver probe, FastAPI `/health/live`, deterministic test helpers, Python checks and split dependency groups.
- `apps/web/` and `package-lock.json`: minimal React/TypeScript page with an explicit foundation state, selected frontend dependencies, Vite/Tailwind, ESLint and type/build scripts.
- `compose.yaml`, `Dockerfile.backend`, `Dockerfile.web`, `Caddyfile`, `docker/postgres/001-app-user.sh`, `.dockerignore`, `.env.example`: pinned foundation images, localhost-only developer database ports, an internal data network, persistent database volumes, health checks, non-root application images and a static web image.
- `Makefile`, `scripts/make_secrets.py`, `scripts/db_probe.py`, `scripts/generate_inventory.py`, `.gitignore`, `LICENSE`, `README.md`: repeatable commands, local secrets, inventory, Apache-2.0 license for new code and project setup.
- `docs/VERSIONS.md`, `docs/THIRD_PARTY.md`, dependency inventory CSVs, `docs/SECRETS.md`, `docs/adr/0001-foundation.md`, status/build-log/known-issues files: package, image, model and architecture records. ## Failures encountered and repaired

1. The first `uv sync` failed because `README.md` was missing from package metadata. Added the file and retried successfully.
2. npm's first install stalled while fetching optional packages. A clean lock-only resolution with bounded sockets succeeded. The unconstrained TypeScript 7 release conflicted with `typescript-eslint` and `openapi-typescript`; TypeScript 5.9.3 was selected and locked.
3. Neo4j initially restarted because its non-root process could not read the mode-0600 bind-mounted secret. The secret file is now mode 0644 inside a mode-0700 host directory; container health and driver authentication passed.
4. The initial PostgreSQL app role had no usable password: its init script ran as the PostgreSQL user and could not read the mode-0600 app secret. The script now checks for a nonempty readable secret, the file mode is 0644 within the restricted directory, the local role was repaired, and a fresh isolated initialization passed. No data volume was deleted.
5. `make check` first found a line-length error in the inventory generator. It was corrected; the final check passed.
