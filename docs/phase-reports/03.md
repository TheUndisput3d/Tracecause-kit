# Phase 03 — OTLP parsing, normalization and redaction

Date: 2026-10-10. Status: **PASS** for R04. Prerequisites: Phase 01 contracts and Phase 02 fixtures passed; Phase 02 commit `751e150`.

## Goal, implementation and files

The importer parses bounded single-request OTLP JSON or NDJSON export requests and traverses resource/scope/span levels without reading the whole NDJSON source. It records byte offset, line number, resource index, scope index and span index. IDs are normalized from case-insensitive hex; nanoseconds remain exact decimal strings at JSON boundaries. Invalid IDs, times, enum values, nesting, file size and line size are rejected with sanitized codes. Unknown source signals and gzip are explicitly unsupported. Missing service identity remains unresolved; missing parents carry quality flags. An alias registry binds exact workspace/namespace/environment/name tuples with a version and provenance reference. `src/tracecause/ingestion/otlp_json.py`, `normalize.py`, `identity.py` and `redaction.py` implement these behaviors.

Redaction is allowlist-first before normalized output. It retains selected typed status/method/error-category values, drops arbitrary attributes and messages, and replaces unsafe or dynamic operation names. Identical duplicate span keys are counted once. Conflicting duplicate keys quarantine both versions and are removed from output. `tracecause normalize` accepts a validated one-source episode, confines a fresh output directory beneath an explicit artifact root, and writes a safe `report.json` plus redacted `spans.jsonl` only on acceptance. Strict mode fails on rejected records; `--allow-partial` preserves valid nonconflicting spans and reports partial status. Source/hash and redacted-output/hash remain distinct.

## Decisions, security/data implications and limitations

ADR 0003 documents strict hex OTLP JSON and conservative redaction. The official upstream example is an interoperability fixture, not a captured trace. A named Collector file adapter rejects inputs until an actual pinned exporter capture can be verified in Phase 12. The CLI currently handles one trace source per episode and has no database persistence; Phase 04 adds durable artifacts and jobs. Redaction may discard useful context and cannot guarantee detection of every novel identifier. Raw input bytes remain in their source directory and are never emitted by this CLI. No captured data, model inference or investigation accuracy is claimed. No Phase 03 gate remains blocked. R04: **PASS**. Next: Phase 04 persistence and durable jobs.
