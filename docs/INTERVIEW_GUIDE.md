# Technical interview guide

| Topic | Explain with repository evidence |
|---|---|
| Why PostgreSQL plus Neo4j? | SQL/artifacts are authoritative, graph snapshots optimize bounded relationship reads. Show membership hash, READY publication and rebuild checks. Discuss cross-store publication and recovery rather than claiming an atomic distributed transaction. |
| How are call edges inferred? | Exact trace/parent span identity, service resolution, kind and compatible timing. Missing parents are explicit. An edge means observed communication, not a causal effect. |
| How is infrastructure knowledge grounded? | Supervisor receipts record actual release archives, runtime process identity, host metadata and configuration writes. Traces independently supply measurements. Ownership is an authored assignment. Show the source receipt and its hash; one local host does not establish cloud discovery coverage. |
| How are asynchronous dependencies represented? | A direct producer/consumer parent pair becomes MESSAGE_FLOW with exact normalized source records and offsets. It is distinct from CALLS; no synchronous broker-to-worker relationship is invented. Explain missing span links and the one-hour derivation bound. |
| What makes the change analysis functional KG reasoning? | Join change→service→runtime/version with bounded dependency paths and source-verified degradation onset. Explain the downstream-degradation priority and show its supporting paths, competing changes and ambiguous same-bucket timing. It is a heuristic, not causal identification. |
| What prevents temporal leakage? | Bind workspace/episode/snapshot/cutoff/mode in backend queries; reject unsupported availability replay; filter before retrieval. Show the25-episode diagnostic with0eligible future items versus109/300 in the deliberately unrestricted arm. This is a leakage diagnostic, not an earlier-cutoff accuracy score. |
| How does the KG answer a useful question? | Follow a symptom through directed observed calls to an unambiguous service-linked authored check. Each hop and quote has a source; exact assertions and service links are checked against immutable bytes. Eight controlled topology cases demonstrate 21/21 expected checks versus 8/21 direct lookups, not diagnosis accuracy. |
| How do you compare graphs over time? | Pin a response within the same episode/snapshot/replay mode, compare directed endpoints at a later cutoff, and open each source at its original cutoff. A six-minute lookback means missing edges can reflect windowing or traffic. |
| How are prior incidents compared? | Pin completed earlier snapshots from the same application/environment; compare service, typed-dependency and anomaly overlap, then cite both sides of state differences. Missing state remains unknown. Current availability replay requires all prior evidence known by its cutoff; prior citations retain their original event-time inspection scope. |
| What does the new operational evaluation establish? | Six controlled real captures across three topologies test review ordering against same-source baselines and ablations. The scenario-aware policy was frozen before the API run; this is not an unseen production benchmark. Report graph and temporal ablations separately, including any tied result. |
| What is candidate recall? | Whether an accepted identifiable target appears before ranking. A target absent from candidates is an end-to-end failure, even if conditional ranking looks good. Keep abstention and answer coverage separate. |
| How was ranking fitted? | Group-aware training folds, training-only imputation/scaling, C selection on training folds and rejection selection on development. Explain the small denominators and previously opened synthetic test labels. No request-handler training or pickle loading. |
| Why retain a heuristic? | Frozen v3 captured development reached 0/5. Experimental v4 reached 5/5 there but regressed synthetic development from 10/10 to 8/10. Small development denominators and domain shift do not justify replacing the default automatically. |
| What can the LLM change? | Only a focus and allowed fact IDs after ranking. Server code compiles exact prose, values and citations, then validates source support again. It cannot issue queries or mutate infrastructure. Structured validity still does not prove semantic usefulness. |
| Why a durable model fence? | A caller timeout/process crash does not prove a provider stopped. The stable locked inode preserves uncertain state; later calls are blocked until dedicated-provider restart is verified. |
| How does snapshot consistency survive failures? | Publish immutable content only after graph validation, preserve prior active snapshot, pin queued jobs/readers and retain snapshots referenced by saved reports or newer historical memberships. Long operational reads renew leases and fail on loss. Explain source membership backfill limits. |
| What did recovery prove? | Exact SQL schema/counts/artifact hashes, graph reconstruction, saved citation replay and a new template result. Same-schema image rollback is narrower than arbitrary migration rollback. |
| What did review not prove? | No independent human adjudication, production accuracy, zero exporter loss, calibrated causal probability, public security assessment or service-level latency guarantee. |

For follow-up questions, open source/tests and actual phase artifacts. Explain
uncertainty and negative findings directly; do not replace them with architecture
buzzwords or a single unsupported accuracy percentage.
